# БотаникАрт Каталог

Закрытая мобильная панель `/catalogue/`. На iPhone: Safari → «Поделиться» → «На экран Домой». Сессия сохраняется до 30 дней; выход и смена ревизии пароля прекращают доступ.

## Данные и редактирование

SQLite находится в `api/.private/catalogue/catalogue.sqlite`, контакты и платежи — в защищённом `api/.private/orders`. Публикация кода не заменяет базу, фотографии, пароли и заказы. Авторизация, проверка источника POST и CSRF обязательны для изменений.

Происхождение товара (`flowwow`, `avito`, `manual`) сохраняется независимо от площадок. Импорт Flowwow обновляет нетронутые карточки каждый час. При ручном изменении содержимого карточка становится `managed`: следующий импорт сохраняет её содержание. Изменение одной видимости не передаёт управление содержимым сайту.

Все источники доступны для редактирования. Удаление переводит карточку в восстанавливаемый архив; импорт не воскрешает её. При восстановлении ранее отключённые площадки не включаются автоматически. Версии защищают от перезаписи параллельных правок. Перед изменениями сохраняются резервные копии.

Категории сайта: флорариум, живая композиция, комнатное растение, растение для флорариума, материалы и декор. Публичная навигация объединяет их в три раздела; у растений две подкатегории.

## Публикация

Метки определяются `product_channels`. Можно выбрать Авито и Flowwow вместе; «Сайт» показывается только при отсутствии выбранных внешних площадок. Выбор площадки не равен подтверждённой публикации: ошибки и ожидание отмечаются отдельно.

При сохранении настройки и очередь намерений записываются одной транзакцией. `PublicationRunner` отправляет только актуальную ревизию; повторные правки объединяются. Результат старой задачи не перезаписывает новую. Выполнение запускается после сохранения и плановой публикацией GitHub Actions. Ключи находятся в приватном `marketplaces-config.php`.

### Авито

`api/avito-feed.php` формирует XML для настроенной загрузки по ссылке. Невалидный или пустой экспорт возвращает 503. Платные продвижения не включаются. При появлении явно выбранного валидного товара отправитель может возобновить расписание, сохраняя ссылку, почту и расписание кабинета. Отчёты API обновляют статусы карточек.

Существующие объявления связаны по ID из исходной выгрузки. Несколько вариантов сайта могут относиться к одному объявлению: их настройки площадки общие, в XML появляется одна запись с исходным AvitoId. Новые карточки получают стабильный ID. Снятие с Авито выполняется вручную; выключение переключателя останавливает отправку карточки. При отсутствии выбранных товаров собственный профиль автозагрузки может быть приостановлен и возобновлён при следующем явном включении товара.

Тестовое объявление «Шепот леса» №8372559354 отключено, владелец снял его вручную. Миграция выводит старые непроверенные исходящие задания из очереди. Не публиковать тестовые товары без согласования владельца.

### Flowwow

`FlowwowPublisher` использует Seller API: чтение, привязка offerId, создание/изменение, скрытие/возврат. Существующие тип и подкатегория сохраняются, полная структура свойств восстанавливается из исходной карточки. Стабильный offerId предотвращает повторное создание после ошибки ответа. Входящий импорт распознаёт созданную нами карточку и связывает её с исходным товаром вместо дубля.

Тип 2 и арендованные товары не изменяются этим адаптером. Архив восстанавливается в кабинете Flowwow. Для новых товаров требуются поля выбранной категории и подходящие фотографии; изображения не увеличиваются искусственно. Схемы и исходные свойства кешируются приватно. При ошибке площадки карточка сохраняется на сайте, а ошибка остаётся в панели. Реальные новые публикации не выполняются автоматическими тестами.

## Заказы и уведомления

В панели видны только реальные подтверждённые покупки и история возвратов. Данные проверяются запросом к банку с сопоставлением заказа, paymentId и суммы. Нельзя вручную отметить неоплаченное оплаченным. Статус доставки `open/completed` независим от банковского статуса; отметка выполнения не возвращает деньги и не снимает резерв.

После подтверждения платежа создаётся уведомление на fridrikova@mail.ru. Отправка использует PHP mail хостинга, отдельную блокировку и повторные попытки. Успешный mail означает приём письма сервером, а не доказанную доставку во входящие. DEMO-покупки не отправляют письма и не попадают в список реальных заказов. Однократный `console.php notifications-check` отправляет явно обозначенное проверочное письмо и проверяет доступность Telegram без ключей.

Возврат из банка проверяет результат, затем открывает Telegram с соответствующим черновиком; покупатель отправляет его сам. Банковский подписанный reference не попадает в ссылку Telegram. Ошибка или возврат оплаты не обозначаются как успешная покупка.

Автоматического уменьшения остатков на других площадках после покупки на сайте нет. Это отдельно от защиты сайта от двойной покупки одного экземпляра.

## Проверки

PHP: `payments.php`, `orders.php`, `catalogue.php`, `publications.php`, `publication-editing.php`, `avito-feed.php` в `hosting/tests`. HTTP: `check_api.py`, `check_catalogue_api.py`; возврат из банка: `node hosting/tests/payment-result.cjs`. Тесты изолированы от реальных публикаций и списаний.

Напоминания Авито показываются за 7 и 3 дня до указанной даты продления, время московское. При закрытом приложении push-уведомлений нет. После продления дату нужно обновить в «Площадки».
