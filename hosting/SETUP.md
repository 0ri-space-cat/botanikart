# БотаникАрт на Timeweb

Нужен обычный виртуальный хостинг с PHP 8.3+, расширениями cURL, mbstring, OpenSSL и SSH/SFTP. Постоянный серверный процесс не нужен. Заказы сохраняются в закрытой папке; для небольшой студии отдельная база данных не требуется.

## Действия пользователя

1. Подключить виртуальный хостинг **Year** на тестовый период. Не выбирать конструктор, VDS, премиальные тарифы и дополнительные платные услуги.
2. Включить SSH в статусе сервисов. SFTP использует тот же доступ.
3. Получить адрес сервера вида `имя.timeweb.ru`, логин хостинга и путь к папке сайта `.../public_html`. Эти значения можно передать в чат.
4. Добавить выданный публичный SSH-ключ отдельной строкой в `~/.ssh/authorized_keys` через файловый менеджер или веб-терминал. Права папки `.ssh` — 700, файла — 600. Существующие ключи сохранять. Если это неудобно, агент подготовит обычный Терминал macOS, пользователь введёт пароль в скрытый ввод.
5. При первом соединении сверить отпечаток сервера с панелью/поддержкой Timeweb. Сохранить подтверждённую запись `known_hosts`.

Пароль Timeweb и ключи банка не присылать в чат. API управления Timeweb для загрузки файлов не нужен.

## Файлы на сервере

```text
папка-сайта/
├── public_html/             ← веб-корень: страницы, assets, data, api
└── botanikart-private/      ← вне веб-корня, права 700
    ├── PaymentService.php
    ├── config.php          ← секреты, создаётся на сервере, права 600
    ├── config.example.php
    ├── configure.php
    ├── console.php
    └── orders/             ← контакты, статусы, резервы; не загружать в GitHub
```

ZIP распаковывать **в папку над public_html**, не внутрь public_html. До загрузки сохранить существующий сайт. При другом имени веб-корня задать настоящий `catalog_path` в приватной конфигурации и `BOTANIKART_PRIVATE_DIR` в окружении PHP.

## Подключение оплаты

1. Загрузить обе части, выбрать PHP 8.3+. Проверить недоступность закрытой папки по HTTP.
2. Настроить HTTPS на техническом адресе хостинга или временном поддомене. Основной домен переключать после проверки, сохранив почтовые MX/SPF/DKIM.
3. Через SSH выполнить `php /полный/путь/botanikart-private/configure.php`. Пользователь вводит DEMO Terminal Key и пароль в скрытый ввод. Скрипт создаёт отдельный секрет подписи заказа. Повторная публикация сохраняет config.php и заказы.
4. Выполнить `php /полный/путь/botanikart-private/console.php doctor`. Это проверка PHP и TLS банка без создания платежа. При недостающей цепочке доверия подключить официальный доверенный сертификат через `ca_bundle`. Не отключать TLS-проверку.
5. В тестовом терминале банка включить HTTP-уведомления на `https://адрес-сайта/api/notify.php`. Адрес также передаётся при создании платежа. Обработчик проверяет подпись и реальный статус банка, затем сохраняет его и отвечает `OK`.
6. Для DEMO-проверки на временном сайте включить `BOTANIKART_PAYMENT_ENABLED` в `data/payment-config.js`. Проверить тестовую оплату, отказ, повторный клик, страницу результата и сохранённый заказ. DEMO не списывает реальные деньги.
7. Настроить cron раз в 5 минут: `php /полный/путь/botanikart-private/console.php reconcile`. В бесплатный период Timeweb cron недоступен: запускать вручную, после оплаты тарифа добавить расписание.
8. До рабочего терминала подтвердить кассу, НДС и способ расчёта. УСН «Доходы» известна, НДС неизвестен. Рабочие платежи блокируются при `receipts_ready=false`. Настроить приватный конфиг и провести отдельно согласованный контрольный платёж.
9. После проверки настроить botanikart.ru, SSL, актуальный site_url и банковские уведомления, включить рабочую покупку.

## Заказы и остатки

Сумма берётся из серверного каталога и сверяется с ценой, показанной покупателю. Ключ повторного запроса позволяет повторно отправить ту же форму без создания второго платежа. Между PHP-процессами товар резервируется под файловой блокировкой. Оплаченный экземпляр нельзя купить повторно.

Ссылка банка действует 30 минут. Резерв освобождается только после подтверждённого отказа/отмены банка: одного таймера недостаточно. Обработчик проверяет просроченный платёж и отменяет его. При неопределённом результате связи с банком резерв сохраняется для разбирательства.

Повторную продажу нового экземпляра владелица подтверждает вручную: `php console.php restock PRODUCT_ID`. Возврат денег не означает, что растение можно автоматически продавать снова. Данные DEMO и рабочего терминала хранятся в разных папках.

Flowwow обновляет витрину раз в час. Автоматическое уменьшение его остатков после продажи на нашем сайте пока не реализовано: остатки двух площадок сверяет владелица. Серверный резерв проверяется при покупке, даже если старая карточка ещё показывает наличие.

Файлы заказов нужно резервировать средствами хостинга. Контакты не попадают в ZIP, GitHub или публичный ответ статуса. Отдельного административного интерфейса пока нет: обслуживание через SSH.

## GitHub и публикация

`.github/workflows/timeweb.yml` обновляет Flowwow каждый час и после изменений main, проверяет PHP и собирает сайт. При ошибке API сохраняется предыдущий каталог. После настройки секретов установить переменную репозитория `TIMEWEB_DEPLOY_ENABLED=true`:

- `FLOWWOW_API_KEY` — существующий ключ, сохранить;
- `TIMEWEB_HOST`, `TIMEWEB_USER`, `TIMEWEB_PUBLIC_DIR` — сервер, логин, абсолютная папка сайта;
- `TIMEWEB_SSH_KEY` — отдельный приватный ключ публикации;
- `TIMEWEB_KNOWN_HOSTS` — подтверждённый публичный ключ сервера.

Ключи банка GitHub не получает. Публикация проверяет SSH-сервер и передаёт только разрешённые файлы. Посторонние файлы хостинга, config.php и заказы не удаляются. Старые ненужные файлы на хостинге удаляются адресно после первой проверенной миграции.

## Проверка и сборка

```sh
php hosting/tests/payments.php
python3 scripts/package-timeweb.py /абсолютный/путь/botanikart-timeweb.zip
```

В репозитории только пример конфигурации. Публичная покупка выключена флагом до реального DEMO-теста на Timeweb. Это заметка разработчика; юридические страницы сайта описывают готовую покупку.
